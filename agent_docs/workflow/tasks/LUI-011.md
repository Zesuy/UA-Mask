# LUI-011 — Transactional Init and procd Lifecycle

## ID

`LUI-011`

## 目标

Define and implement one explicit Save & Apply lifecycle in which core validation and atomic JSON generation succeed before a healthy process is reloaded or stopped, with observable failure state for the future UI.

## 实施步骤

1. Trace existing rc.common/procd start, reload, trigger, and stop behavior from the reviewed baseline.
2. Specify enabled, disabled, valid reload, invalid reload, start failure, and recovery state transitions.
3. Ensure candidate generation invokes `UAmask -check-config` and replaces runtime JSON atomically only on success.
4. Ensure invalid candidates do not stop a healthy process before validation.
5. Persist a narrowly scoped last validation/start error artifact for diagnostics; clear it on successful recovery.
6. Ensure one apply event leads to one explicit start/reload/stop action.
7. Add deterministic shell contracts for all state transitions and wire them into core CI.
8. Review shutdown/start behavior for firewall setup ordering without operating a real firewall.

## 验收标准

- Valid enable, reload, and disable transitions are explicit and tested.
- Invalid changes preserve the last valid JSON and healthy process until corrected.
- Error state is available to the future adapter and cleared on success.
- No duplicate lifecycle action occurs per apply.
- CLI, JSON schema, UCI names, and core business code are unchanged.
- All core and OpenWrt contracts pass.

## 风险

- rc.common reload fallback differs from assumptions.
- A preflight could be accidentally executed twice by both UI and procd trigger.
- Error artifact permissions or cleanup could expose stale/misleading state.

## 升级条件

- Correct behavior requires a CLI or JSON schema change.
- procd cannot express the reviewed transaction without a broader public interface.
- Existing production behavior conflicts with a confirmed safety requirement.

Main records and resolves the architecture decision before continuing.
