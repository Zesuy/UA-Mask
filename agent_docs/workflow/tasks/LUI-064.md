# LUI-064 — Remove Rendered Null Placeholders

## ID

`LUI-064`

## 目标

Remove QEMU-confirmed literal `null` text rendered by LuCI 23.05 when optional children are passed into `E()` or DOM child arrays, while preserving every existing status, polling, diagnostics, and recovery behavior.

## 已确认复现

OpenWrt 23.05.5 QEMU at a 375px viewport renders literal `null` text between sections on Overview and Diagnostics. Source review confirms optional nodes are supplied as `null` children, including conditional status notices, optional service links, the metrics empty state, diagnostics recovery, and feedback retry content.

## 实施步骤

1. Build child arrays explicitly and append optional nodes only when present.
2. Preserve all existing branches, labels, ARIA roles, polling, refresh, and action handlers.
3. Add a focused static contract that prevents optional `null` DOM children from returning.
4. Do not alter native theme styling or introduce placeholder markup.

## 验收标准

- No optional `null` value is passed to LuCI `E()`, `dom.content()`, or `replaceChildren()` child collections.
- Existing healthy, unavailable, failed, and recovery content remains semantically unchanged.
- The static contract would fail on the QEMU-confirmed pre-fix source.
- Only the three allowlisted files change.

## 风险

- Filtering all falsey children could accidentally remove valid zero or empty-string content; append only optional DOM nodes.
- A broad source regex could reject legitimate non-DOM state initialized to `null`.

## 升级条件

- The correction requires a shared interface, adapter, package, or settings change.
- Two attempts fail to remove the literal QEMU text without behavior loss.

Stop and report exact evidence to main.
