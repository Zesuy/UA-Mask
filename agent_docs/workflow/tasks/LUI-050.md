## 实施步骤

1. Load structured log, effective config, last error, and status data from fixed adapter methods.
2. Render at most 200 recent log lines in a readable, selectable, wrapping-safe native LuCI container.
3. Add manual refresh with loading, success, and actionable error feedback.
4. Add clear-log with explicit confirmation, disabled in-flight state, and post-action refresh.
5. Render effective JSON safely as text, never HTML.
6. Show latest validation/start error and distinguish stale/no-error/missing-artifact states.
7. Explain enabled-but-not-running and other adapter-defined anomalies with a route to settings or retry.
8. Never accept or transmit a path or arbitrary command from browser input.
9. Ensure keyboard operation, focus feedback, and 375px wrapping.

## 验收标准

- Logs, effective config, errors, and anomaly state render safely.
- Refresh and clear have visible progress and error/success outcomes.
- Clear requires confirmation and cannot target a browser-provided path.
- Missing log/effective/error files produce useful empty states.
- Dynamic content uses text rendering and cannot inject markup.
- Page is keyboard usable and has no horizontal overflow at 375px.

## 风险

- Large log lines or JSON may force horizontal overflow.
- Clear confirmation APIs differ by LuCI version.
- Error output may contain untrusted text and must never be rendered as HTML.

## 升级条件

- Required adapter output is absent or unsafe.
- A shared ACL/adapter/menu/package change is required.
- OpenWrt 23.05 lacks the selected confirmation or notification API.
- Two attempts fail for the same interface incompatibility.

Stop and report to main; do not modify shared files.
