## ID

`LUI-061`

## 目标

Run the complete automated regression suite and verify the built IPK/APK asset/dependency contracts for OpenWrt 23.05.5 and 25.12.5 without broadening implementation scope.

`DONE`

## 实施步骤

1. Confirm worktree scope and no unauthorized changes.
2. Run core CI and the full Go race suite.
3. Run all OpenWrt shell, lifecycle, adapter, JavaScript, menu/ACL, and package-asset contracts.
4. Build or use the pinned SDK workflow for representative OpenWrt 23.05.5 IPK and 25.12.5 APK packages from the current state.
5. Inspect package metadata, dependencies, installed paths, executable bits, and absence of legacy Lua/luci-compat.
6. Record exact command, SDK matrix entry, package hash, and results in central progress.
7. Do not mark green if a build used an unpinned SDK or unreviewed dirty-delivery override.

## 验收标准

- Core CI and full race suite pass.
- Every OpenWrt contract in `verification.md` passes.
- Representative supported IPK and APK builds succeed with pinned SDKs.
- Package contents and dependencies match the migration requirements.
- No tracked implementation changes occur during this verification task.

## 验证命令

```sh
make -C core ci
cd core && go test -race -count=1 ./...
sh openwrt/tests/luci-js-contract-test.sh
sh openwrt/tests/package-assets-test.sh
git diff --check
```

Run `scripts/build-release.sh` with exact entries from `.github/openwrt-sdk-matrix.json` and record the resolved commands/evidence rather than inventing SDK values.

## 风险

- SDKs may be absent locally or require network/cache state unavailable in the session.
- Dirty-worktree safeguards may reject deliverable builds before a commit exists.
- Package inspection tooling differs between IPK and APK.

## 升级条件

- A pinned SDK is unavailable or its hash fails.
- Any automated test or package contract fails.
- Deliverable verification requires a commit, push, physical device, or external authority not granted.

Record the precise blocker; do not use `--allow-dirty` as release evidence or modify implementation.
