# LUI-010 — Canonical UCI Lists and Explicit Defaults

## ID

`LUI-010`

## 目标

Make init accept both existing scalar CSV/space-separated values and canonical UCI lists, and make new-install UCI defaults explicit without changing existing option names or generated JSON semantics.

## 实施步骤

1. Define helper behavior for reading a UCI list or falling back to the legacy scalar separator for the same existing key.
2. Apply it to match keywords, exact pass-through entries, offload keywords, ingress devices, bypass ports, and bypass IPv4/CIDR entries as applicable.
3. Preserve trimming, empty removal, Unicode, quotes, and backslashes.
4. Expand default UCI for new installations using the baseline-reviewed OpenWrt defaults.
5. Keep current section and option names unchanged.
6. Extend tests so equivalent scalar and list inputs produce byte-semantically equivalent parsed JSON and effective config.
7. Do not change lifecycle ordering; `LUI-011` owns that work.

## 验收标准

- Old scalar configurations still generate the same JSON.
- Canonical UCI lists generate equivalent JSON.
- New-install UCI contains explicit reviewed defaults.
- Existing option names and JSON schema v1 are unchanged.
- No JavaScript or core code is added or changed.
- Configuration-generation contracts pass.

## 验证命令

```sh
sh -n openwrt/root/etc/init.d/UAmask

make -C core ci
git diff --check
```

## 风险

- `config_get` and `config_list_foreach` may represent scalar/list values differently across OpenWrt versions.
- A canonical list write could lose a legacy value if normalization is not symmetric.
- Explicit defaults could accidentally change existing-install behavior.

## 升级条件

- Supporting both encodings requires renaming an existing option.
- Equivalent inputs cannot produce equivalent JSON.
- A requested default is unresolved in the baseline matrix.
- The same normalization failure persists after two attempts.

Stop and report exact field/input evidence to main.
