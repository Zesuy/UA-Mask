# LUI-066 — Normalize Unchanged Legacy Scalars on Save

## ID

`LUI-066`

## 目标

Ensure a successful Settings save rewrites loaded legacy scalar list-like options to canonical UCI lists even when the user does not edit the visible list items, preserving equivalent effective configuration and the one-action lifecycle.

## 已确认复现

On OpenWrt 23.05.5 QEMU, Settings expands legacy scalar keywords, exact pass-through, devices, ports, and IPv4/CIDR values correctly. After a successful Save & Apply and exactly one reload, an unrelated scalar field changes but `uci show UAmask` still reports the original scalar list encodings. The inherited form parser skips `write()` when the normalized visible items are semantically unchanged.

## 实施步骤

1. Make the compatibility parser explicitly write every active, valid list-like form value through the existing canonical-list writer, including unchanged lists.
2. Preserve inactive retained fields, validation behavior, explicit empty-list markers, and unknown supported values.
3. Do not add another lifecycle action or browser RPC.
4. Add a focused source contract proving the compatibility parse path writes non-empty arrays rather than delegating unchanged arrays to the inherited parser.

## 验收标准

- Save and Save & Apply canonicalize unchanged legacy CSV and whitespace scalar options.
- Canonical lists and explicit empty lists remain stable on subsequent saves.
- Generated schema-v1/effective configuration stays equivalent apart from intentionally edited fields.
- One Save & Apply still causes exactly one reload.
- Only the two allowlisted files change.

## 风险

- Writing inactive retained options could erase hidden expert/offload settings; write only active options.
- Bypassing standard validation would allow invalid lists; require `isValid(section_id)` before writing.

## 升级条件

- Canonicalization requires changing init normalization, UCI keys, JSON schema, or lifecycle actions.
- Two attempts fail to preserve effective-config equivalence in QEMU.

Stop and report exact evidence to main.
