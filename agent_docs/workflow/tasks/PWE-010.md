# PWE-010 — Unattended Playwright LuCI Product Checks

## ID

`PWE-010`

## 目标

Replace the manual LuCI browser/QEMU loop with a reproducible, unattended Playwright workflow that reuses a provisioned OpenWrt 23.05.5 base, creates a disposable overlay per run, supports fast current-source deployment and exact-package installation, validates all three native JavaScript pages, and always preserves actionable failure evidence.

## 固定设计

1. Use `@playwright/test` pinned to `1.62.1`; pin every additional Node test dependency and commit `package-lock.json`.
2. Keep Playwright dependencies local to `openwrt/tests/e2e/`; do not add a frontend runtime dependency or framework.
3. Use the official OpenWrt 23.05.5 x86/64 ext4 combined image and verify SHA256 `f5c77659a33bd43cba105cf2f75e56d054fa9e0b9a73dc9f2a5bcb0e126ff7d5`.
4. Provision LuCI/dependencies automatically once into an ignored, fingerprinted QEMU base cache. Every test run must create a disposable qcow2 overlay and use QEMU user networking only. Test runs use `restrict=on` with loopback-only SSH/HTTP forwards.
5. Provide two explicit modes:
   - fast source mode: deploy the current binary/config/init/adapter/menu/ACL/views from the worktree without rebuilding or reinstalling an IPK;
   - package mode: install an explicitly supplied exact IPK and verify package identity/assets before browser checks.
6. QEMU lifecycle belongs to shell orchestration. Playwright consumes `LUCI_BASE_URL` and bounded fixture actions; it must not contain arbitrary SSH command construction.
7. Use readiness probes and Playwright web-first assertions. Fixed sleeps are forbidden except for measuring the product's real five-second polling cadence; use bounded timeouts as hang guards.
8. Use a new isolated BrowserContext and UI login. Credentials and storage state remain ignored; do not parse a persistent Chrome profile or commit secrets.
9. Default to `workers: 1` because UCI/procd/log fixtures share one guest. Parallelism requires a separate VM per worker and is outside this task.
10. Always trap cleanup and verify no owned QEMU/Chromium process remains. Never kill by broad process name or unresolved PID.

## Playwright 场景

### Shared rendering and UX

- Overview, Settings, and Diagnostics routes load through native LuCI without Lua compatibility errors.
- Fail on page errors, unexpected console errors, failed UA-Mask resources, literal `null` placeholders, and horizontal overflow.
- Cover 1440×900 desktop and 375×812 phone for all pages; include 812×375 landscape and 768×1024 targeted layout checks.
- Cover native light/dark behavior and reduced-motion.
- Exercise keyboard Tab order, Space/Enter operation, visible focus, no keyboard trap, alert/status semantics, and labeled controls.
- Integrate a pinned axe Playwright dependency for high-impact accessibility checks. Document narrowly justified exclusions rather than disabling broad rule sets.

### Overview

- running, disabled, starting, failed, enabled-not-running, healthy-with-rejected-config, and missing-stats presentations.
- Five-second polling starts at the expected cadence and never overlaps; no runaway requests after navigation/detach.
- Metrics, recovery action, and factual offload/disconnect risk language remain present in applicable states.

### Settings

- Legacy CSV/space-separated scalar values render as separate list items.
- Blank DynamicList add-controls do not block save; malformed non-empty port/IP/regex values remain actionable.
- Save does not perform a lifecycle action. Save & Apply performs exactly one action.
- Active valid unchanged legacy lists are canonicalized; effective schema-v1 JSON remains equivalent except intentional edits.
- Rejected candidates preserve the previous healthy PID and last-valid JSON.

### Diagnostics

- Bounded logs, missing log, effective JSON, missing artifact, current/rejected/failed/recovery error states.
- Whole-page refresh, per-section retry, log refresh, clear-log cancel, and clear-log confirm.
- Destructive confirmation is keyboard-operable and success/error feedback is announced.

## Artifacts and reporting

- Default outputs live only under `dev/luci-e2e/<run-id>/`.
- Retain trace, screenshot, console/network summary, Playwright report, QEMU serial log, fixture/action log, exact source/package identity, browser version, OpenWrt identity, and cleanup result on failure.
- Do not retain video by default. Do not upload credentials, storage state, raw cookies, or unrestricted configuration/log data.
- CI uploads failure artifacts only, with a short retention period.

## Entrypoints and CI

- Add clear Make targets for dependency installation, fast local smoke, full local product checks, and exact-package checks without changing existing default package behavior.
- Add a separate `.github/workflows/luci-e2e.yml`; do not add QEMU/Playwright to `core ci`.
- CI must use a browser compatible with Playwright 1.62.1, cache only verified OpenWrt/browser/npm inputs, run under TCG when KVM is unavailable, and trigger manually plus on relevant LuCI/e2e changes. A scheduled run is acceptable if bounded.
- Local mode may use `CHROMIUM_PATH=/snap/bin/chromium`; CI should use the Playwright-matched browser or official image.

## 验收标准

- A clean machine with declared host prerequisites can prepare the cached base and run without manual guest installation or browser interaction.
- A warm-cache fast smoke requires one command and does not install an IPK.
- Exact-package mode installs only the supplied IPK and proves its three installed views equal the expected sources/package content.
- Running the full suite twice produces the same result and leaves no owned VM/browser process.
- Deliberately breaking a key locator/assertion produces a trace and screenshot and still cleans up.
- Existing core/OpenWrt contracts remain green and production files remain unchanged.

## 验证命令

Run every new documented lint/unit/dry-run command and, when host prerequisites are present, both fast and exact-package smoke. Finish with:

```sh
make -C core ci
cd core && go test -race -count=1 ./...
sh openwrt/tests/luci-js-contract-test.sh
sh openwrt/tests/package-assets-test.sh
git diff --check
git status --short
```

## 风险与升级条件

- Stop if automation would require a physical device, host firewall mutation, broad process termination, real host runtime artifacts, unverified images, or committed credentials.
- Stop and report if a fully fresh bootstrap cannot resolve pinned LuCI dependencies reproducibly.
- Do not change production code to make a locator convenient. If native semantic locators are insufficient, report the exact missing accessibility contract to main.
- Do not silently waive a browser/OpenWrt version mismatch or convert package verification into source-copy verification.
