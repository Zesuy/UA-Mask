## 已确认复现

On OpenWrt 23.05.5 QEMU, Settings correctly expands legacy `keywords='Android,Legacy Phone'` into two visible items. Clicking Save & Apply fails before UCI write with:

```text
Option "Match keyword substrings" contains an invalid input value.
Add a non-empty keyword or remove the empty item.
```

The blank value is the normal DynamicList add-control, not a saved list item. The same validator shape exists for optional offload keywords, bypass ports, and bypass IPv4/CIDR fields.

## 实施步骤

1. Make every DynamicList item validator accept the blank add-control while continuing to reject malformed non-empty values.
2. Preserve canonical list writes, the explicit empty-list marker, legacy scalar expansion, field-local errors, and authoritative core validation.
3. Cover keywords, offload keywords, bypass ports, and bypass IPv4/CIDR consistently.
4. Add a focused source contract that fails on the pre-fix validator behavior without coupling to generated IDs.

## 验收标准

- A loaded valid legacy scalar list can Save & Apply with the editor blank.
- Non-empty malformed ports and IPv4/CIDR values still fail field-local validation.
- Canonical list and explicit empty-list storage behavior is unchanged.
- No lifecycle, UCI key, schema, adapter, or package interface changes.
- Only the two allowlisted files change.

## 风险

- Treating every blank scalar field as valid would weaken required non-list validation; scope the behavior to DynamicList item validators only.
- Removing custom validation entirely would make older LuCI inline errors less actionable.
