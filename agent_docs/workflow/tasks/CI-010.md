## CLI 契约

```sh
python3 openwrt/tests/runtime-smoke/run.py \
  --openwrt 23.05.5 \
  --package /absolute/UAmask.ipk \
  --metadata /absolute/UAmask.ipk.metadata.json \
  --run-dir /absolute/new-run \
  --cache-dir /absolute/image-cache
```

- 同样支持 25.12.5/.apk。
- 可选 --image-file /absolute/official.img.gz：仅复用已经通过 manifest SHA256 校验的镜像。
- 可选 --fail-after boot：故意在 guest 就绪后失败，用于主控检查失败证据与清理；进程仍须非零退出，不能把实际失败吞成 PASS。
- --help 可在仅标准库环境运行。除宿主现有 QEMU、qemu-img、SSH/SCP、ssh-keygen 等命令，Python 只用标准库。

## 平台与执行边界

platforms.json 固定两个版本 x86/64 generic-ext4-combined.img.gz 的官方 HTTPS URL 与官方 sha256sums 中的 SHA256。可以联网读取官方校验和；不得编造或使用可变 snapshot。

只读 raw base + disposable qcow2 overlay；只用 QEMU user networking，hostfwd 绑定127.0.0.1。不得修改基础镜像。应支持KVM，缺失时TCG，记录实际选择。有界 readiness 轮询只用于guest/网络就绪，不用固定sleep判断成功。用独立运行目录拒绝覆盖已有结果，超时须终止自己创建的进程并等待。仅删除自己创建的overlay/key，失败也保留日志。

可用 serial Unix socket bootstrap dropbear authorized_keys，再通过独立 SSH 执行；所有测试用私钥放 run-dir/private 并在finally删除，上传工件不得包含私钥、密码、cookie。串口命令只能含公钥。guest 出网可用于安装官方版本依赖；必须记录阶段与失败，不能以 --force-depends/--force-broken-world 绕过真实依赖检查。允许本地包 --allow-untrusted（CI临时SDK签名），不得将此表述为正式签名验证。

## 验证场景

1. 下载/校验官方镜像，验证安装包sha256与metadata；metadata中的OpenWrt/架构/格式匹配所选平台，artifact basename正确且来源commit为合法40位SHA。
2. 从干净overlay启动，记录 /etc/openwrt_release、uname、boot_id，确认guest版本。
3. 正常安装精确IPK/APK与声明依赖，不跳过依赖；保存package DB、安装日志。包版本必须等于metadata.package_version加平台release后缀；已安装core的`-v`必须精确等于metadata.version。
4. 默认disabled启动无运行进程；通过UCI开启，启动后确认procd实例、PID、监听、生成JSON通过core -check-config；停止后确认进程停止；restart后确认新进程与有效配置。
5. 对非法JSON直接运行core -check-config，确认拒绝且当前服务仍存活（不声称旧init具备尚未实现的事务性UCI应用）。
6. 验证当前包布局的Lua或JS资产存在、LuCI入口HTTP可达（可显式安装/启动uhttpd作为夹具）。不把HTTP200当浏览器全流程通过。
7. 采集guest logread、service/进程/监听、nft或iptables快照。failure路径尽力取证；输出结论、failed_stage、错误、package/source身份与cleanup。

## 产物契约

- result.json：schema_version、status PASS/FAIL/ERROR、source_commit、package_sha256、openwrt、failed_stage、error、cleanup（qemu_stopped、overlay_removed、private_material_removed）。任意cleanup失败必须非零并不可PASS。
- events.jsonl：每阶段start/end/fail，UTC时间、monotonic duration、结果；操作输出落独立可读文件。
- qemu-serial.log、qemu-stderr.log、guest-identity.txt、package-install.txt、package-status.txt、service-checks.txt、guest-diagnostics.txt。
- outcome在finally清理完成后生成；preflight失败也应有result/events。证据不能被下一次运行覆盖。
