## 实施步骤

1. Build a `form.Map('UAmask')` with sections/tabs for basics, matching, traffic scope, smart offload, and expert performance.
2. Preserve every existing section/option name and current supported behavior.
3. Use `DynamicList` for keywords, exact pass-through, and offload keywords.
4. Use `DeviceSelect` for ingress devices and itemized validated inputs for ports and IPv4/CIDR values.
5. Make field reads tolerate the reviewed legacy scalar formats and writes use canonical list representation.
6. Add numeric datatypes/ranges, units, and inline error text aligned with core/init constraints.
7. Show regex only in regex mode and custom resource settings only for the custom profile.
8. Show disconnect-on-match only in the relevant keyword-offload state.
9. Rewrite labels/descriptions in plain language, clearly distinguishing exact pass-through and substring target offload.
10. Use explicit risk copy before enabling target bypass or disruptive disconnect behavior.
11. Use native Save & Apply and the reviewed single lifecycle; do not add a duplicate direct restart.
12. Keep advanced terms such as GOGC behind expert disclosure with safe defaults.

## 验收标准

- Existing UCI options load without manual migration or data loss.
- Saving converts list-like values to canonical UCI lists.
- Dependencies and progressive disclosure match product requirements.
- Invalid numeric/list inputs show field-local actionable messages.
- No label claims encrypted or all network traffic is rewritten.
- Dangerous actions explain bypass duration/consequence and potential UA leakage.
- Basic configuration does not require separators or expert performance knowledge.
- Page is keyboard usable and has no 375px horizontal overflow.

## 风险

- LuCI `DynamicList` scalar behavior may differ across versions.
- `DeviceSelect` storage may not match the stabilized init list contract.
- JavaScript regex validation must not claim equivalence with Go RE2.
- Custom Save & Apply handling could accidentally duplicate procd reload.

## 升级条件

- A required option cannot retain its existing key and achieve canonical list behavior.
- A shared lifecycle/adapter/menu/ACL change is required.
- A form API required by the design is unavailable on OpenWrt 23.05.
- Two attempts fail for the same legacy round-trip issue.

Stop and report exact evidence to main; do not modify shared files.
